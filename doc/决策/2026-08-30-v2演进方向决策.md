# quick-toolbar v2 演进方向决策（2026-08-30）

- 对象：v2 开放问题（v1 设计 §9）的方向拍板与边界，供实现期对照（不重开辩论）。
- 设计细节见 `doc/设计/2026-08-30-quick-toolbar-v2设计.md`。

## 决策

### V2-1. 行为 = 引擎能力，适配器 = 数据（扩展任何行为的先决约束）
v1 已定「适配器只允许枚举+数据（LLM 不可信输入）」。v2 补 `open-settings`/`command` 等行为时**维持该边界**：新能力一律作为引擎行为实现（可信代码），适配器仍只写数据；`adapters.prompt.md` 明示「行为枚举=引擎内置，适配器不携带代码」。
- 反对方案：适配器内嵌函数式。理由：LLM 产物/用户配置不可信，函数逃逸 zod 防线（任意执行风险）。
- 备注：v1 设计 §3 曾提「v2 开放函数式+信任模式」——**本决策修正该方向**：不开放函数式；以「行为库持续扩容」替代（白名单式增长，安全边界清晰）。
- 例外：若出现「行为枚举表达不了的场景」，走「新行为提案 → 引擎升级」流程，而非适配器写函数。

### V2-2. 半自动发现 = 建议制，永不自动启用
「未识别按钮」扫描/匹配/提示词产出，仅输出候选与提示词，**不自动生成/写入适配器、不自动触发**。
- 理由：自动启用 = 不可信决策（误点/误隐藏风险）；产品哲学是「LLM=驻场工程师，人最后拍板」。

### V2-3. 扩展包 = 数据包（非代码包）
适配器扩展包格式仅含 `adapters` 数组 + 元数据（pack/version/target），校验复用 zod 用户配置 schema；不引入「包内脚本」。
- 优先级合流：内置 < 用户配置 < 扩展包（同 id 后着覆盖）。

### V2-4. ui-slots 整合 = 探测后整合，官方无公开 slot 则维持现载体
- 先查证（调研点⑤）后动手；无公开「命令入口」slot → 记录「已查证无」并维持 DOM 载体，不为此重构。
- 整合只换容器，不换交互模型（morph/定位闭环/几何判定不动）。

### V2-5. 壳适配器拆分 = 解耦发行，功能不变
`src/client.ts` 拆 carrier 层（web-float / shell-titlebar / shared）；**拆分当轮以「思灵与 web 行为与 v1.11 完全一致」为验收**（回归对照），不接受拆坏再修。
- 壳库侧桥接（`ssid:title:action` IPC）继续留在 SSiD 壳库 main.mjs，quick-toolbar 不 import 壳库内部。

### V2-6. v2 里程碑顺序（用户拍板）
M1 行为补齐（open-settings/command）→ M2 半自动发现 → M3 壳拆分 → M4 扩展包/ui-slots（依调研结果取舍）。
- 理由：#1 补齐行为是「适配覆盖度」刚需（设置/命令类按钮现网占比高）；#2 半自动发现是驻场闭环的最后一环；#3 拆壳是发版解耦前提；#4 生态/官方整合依赖调研结论，后置。

### V2-7. 标题栏「悬浮球」开关（2026-08-30 M1 期间用户拍板）
- 用户体验后确认悬浮球好用 → **SSiD 壳标题栏加开关按钮**（圆圈+圆点图标；开启有点/关闭空圈，回弹动画）。
- 语义：壳环境悬浮球**默认隐藏**（标题栏接管入口不变）；开关开启后显示（`ssid:titlebar detail='quick-toolbar-toggle'`；状态持久化）。
- 实现形态：titlebar.html/js 按钮 + 事件桥（`ssid:title:action` 通用字符串）+ quick-toolbar client `__SSID_SHELL__` 守卫改「默认隐藏+开关」。
- 属 **M3 壳适配拆分的前置雏形**（壳 UI 契约纳入拆分范围）。

### V2-8. 状态持久化 = host 化（2026-08-30 用户规约，手册 §7.10）
- 规约：**DSH 页面跨重启状态一律 host 化**（存 `~/.dsh/<pkg>.json`，host 半读写 + 客户端 API 桥）；页面 localStorage 只允许会话瞬时态。
- 背景：思灵内核 web 端口动态 → localStorage 按 origin（host:port）隔离 → 跨重启必丢（quick-toolbar 位置/钉住/折叠/壳开关 2026-08-30、panels 更新日志 seen 2026-08-28 两次实踩）。
- 落地（M1 期间完成）：`/quick-toolbar/api/state`（GET/POST + 原子写 + normalizeState 字段级回退）+ 客户端 loadState/saveState；标题栏初始图标由 main.mjs 直接读文件。
- 红线：**禁止在插件页面用 localStorage 保存持久状态**（后续所有功能遵守）。

### V2-9. 插件=载体平台，注册=驻场 LLM 域（2026-08-30 产品理念定稿）
- **理念**：quick-toolbar 是**聚合器平台**——提供注册协议（schema/图纸/渲染执行器）；**任何环境的具体按钮适配由当场的 LLM 自主完成**（探查 + 注册为"按钮子插件"，DSH「一切皆插件」落地）。**不存在能预适配所有场景的"完美脚本"**——把发现/适配固化进插件代码是传统插件思维（预写兼容代码），应避免。
- **红线**：插件内**不实现**任何"扫描/发现/候选/提示词生成"逻辑（v0.4.0 scout 已回撤，经验记录在案）；LLM 图纸（adapters.prompt.md）写明"自主探查（浏览器/code 能力验证选择器）→ 注册"。
- 家族旁证：dsh-better-sidebar 同构——官方不内置、由生态通过同一套 **ctx.betterSidebar** API 注册（其注册者是插件，我们更抽象：注册者 = LLM 数据注册；理念一致、层次更下沉）。
- **粒度分界（用户补充定稿）**：功能面多大，注册形态就多重——**快捷按钮**（无其他功能面）= LLM 数据注入（一条 JSON 即注册，独立插件打包/生命周期过重）；**完整功能**（大 UI/状态面）= 独立插件注册（better-sidebar 的 registerTab/registerFileViewer 形态）。quick-toolbar 属前者。
- 推论：适配器数据应保持**纯数据 + 枚举行为**（V2-1），以便 LLM 生成、zod 校验、人最后拍板。

### V2-10. 范式定位：「有条件成立」即次世代形态（2026-08-30 用户校准）
- **标尺校准**：以「完整而鲁棒 = 静态代码预适配所有场景」为标尺是**无 LLM 辅助的前时代标尺**；LLM 运行时范式的形态就是「有条件成立」——**条件本身就是范式定义**（LLM 在场、能行动、协议存在），不是缺陷。本哲学不是退化的鲁棒哲学，而是次世代范式。
- **条件由生态自带（用户校准）**：插件专属 DSH（LLM 运行时）→ **LLM 必然在场、能力面一致**（浏览器/代码/工具齐全）——「LLM 不在场/能力不足」场景基本不存在，不是责任项。剩余责任仅两条：①**协议文档质量 = 产品下限**（adapters.prompt.md/任务书，锚点测试防漂移）；②**信任敞口**（窄接口 + 纯数据已控：LLM 当抄写员不当执行者——行为白名单 5 种 kind，非代码注入）。
- **实证轨迹（第三方同路，非孤例）**：
  - Apple iOS 26.1 起**系统级 MCP 支持** + App Intents = 载体插槽（LLM 调用 App 能力的标准槽）；
  - WWDC26 Siri **屏幕感知**（LLM 直接读屏幕实体文本表示）= 现场理解，与本方案「LLM 探查 DOM 验证选择器」同构；
  - WWDC26 **Foundation Models 框架**成为系统框架 = LLM 是运行时一部分而非外部服务；
  - DSH 即 LLM 运行时：插件注册 = 工具注入；工具栏载体比 Apple 更轻一层（只注册数据，不写代码）。
  - 来源：iOS 26.1 MCP（livemint.com、163.com 报道）、WWDC26 视频 241/343（developer.apple.com）。
- 对应行动：**把协议和引导做扎实**（V2-11 起），而不是把适配逻辑写回插件（V2-9 红线）。

### V2-11. 会话发起实践：LLM 交互闭环的最后一公里（2026-08-30 实证）
- **交付物**：工具栏面板 ➕「添加按钮」→ 创建专业会话并注入注册任务书 queue 执行（v0.5.1 落地）——解决载体哲学**冷启动**（用户不知道"开会话让 LLM 做"）。
- **机制（实证，插件中心 LLM 更新同款）**：client 半 `exports.inject = ['sessions','workspaces','uiWorkspace']` → apply ctx 按 fiber.inject 白名单发服务 → `ctx.uiWorkspace.connectWorkspace(wsId)` 得会话 id → `ctx.sessions.binding(id).session.prompt([{type:'text',text}],'queue')` 注入并自动执行 → `session.rename`/`sessions.open`。workspace 目标取 `ctx.workspaces.list.getSnapshot().items[].workspaceId`（无 recentWorkspaceId，items[0]=最近工作区兜底）。
- **降级链**：服务缺失/失败 → composer 草稿注入（用户 Enter 发送，功能完整仅少会话隔离）——按钮永不失能。
- **教训**：2026-08-30「DSH 无第三方可用的创建会话通道」为**错误结论**——根因是 exports.inject=[] 未声明（cordis-client-runner guard.ts：未声明=不可见、声明而缺失=undefined 可降级）；此前只证「未声明不可见」就记成「不存在」。**「不支持/不存在」类结论先 memory_search 既有排查记录**（插件中心排查记忆 81a42ccf 早载同款结论）。
