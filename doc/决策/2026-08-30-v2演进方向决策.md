# quick-toolbar v2 演进方向决策（2026-08-30）

- 对象：v2 开放问题（v1 设计 §9）的方向拍板与边界，供实现期对照（不重开辩论）。
- 设计细节见 `doc/设计/2026-08-30-quick-toolbar-v2设计.md`。

## 决策

### V2-1. 行为 = 引擎能力，适配器 = 数据（扩展任何行为的先决约束）
v1 已定「适配器只允许枚举+数据（LLM 不可信输入）」。v2 补 `open-settings`/`command` 等行为时**维持该边界**：新能力一律作为引擎行为实现（可信代码），适配器仍只写数据；`adapters.prompt.md` 明示「行为枚举=引擎内置，适配器不携带代码」。
- 反对方案：适配器内嵌函数式。理由：LLM 产物/用户配置不可信，函数逃逸 zod 防线（任意执行风险）。
- 备注：v1 设计 §3 曾提「v2 开放函数式+信任模式」——**本决策修正该方向**：不开放函数式；以「行为库持续扩容」替代（白名单式增长，安全边界清晰）。
- 例外：若出现「行为枚举表达不了的场景」，走「新行为提案 → 引擎升级」流程，而非适配器写函数。

### V2-2. 半自动发现 = 建议制，永不自动启用
「未识别按钮」扫描/匹配/提示词产出，仅输出候选与提示词，**不自动生成/写入适配器、不自动触发**。
- 理由：自动启用 = 不可信决策（误点/误隐藏风险）；产品哲学是「LLM=驻场工程师，人最后拍板」。

### V2-3. 扩展包 = 数据包（非代码包）
适配器扩展包格式仅含 `adapters` 数组 + 元数据（pack/version/target），校验复用 zod 用户配置 schema；不引入「包内脚本」。
- 优先级合流：内置 < 用户配置 < 扩展包（同 id 后着覆盖）。

### V2-4. ui-slots 整合 = 探测后整合，官方无公开 slot 则维持现载体
- 先查证（调研点⑤）后动手；无公开「命令入口」slot → 记录「已查证无」并维持 DOM 载体，不为此重构。
- 整合只换容器，不换交互模型（morph/定位闭环/几何判定不动）。

### V2-5. 壳适配器拆分 = 解耦发行，功能不变
`src/client.ts` 拆 carrier 层（web-float / shell-titlebar / shared）；**拆分当轮以「思灵与 web 行为与 v1.11 完全一致」为验收**（回归对照），不接受拆坏再修。
- 壳库侧桥接（`ssid:title:action` IPC）继续留在 SSiD 壳库 main.mjs，quick-toolbar 不 import 壳库内部。

### V2-6. v2 里程碑顺序（用户拍板）
M1 行为补齐（open-settings/command）→ M2 半自动发现 → M3 壳拆分 → M4 扩展包/ui-slots（依调研结果取舍）。
- 理由：#1 补齐行为是「适配覆盖度」刚需（设置/命令类按钮现网占比高）；#2 半自动发现是驻场闭环的最后一环；#3 拆壳是发版解耦前提；#4 生态/官方整合依赖调研结论，后置。

## 遗留调研点（落地前查证，禁止凭记忆下结论）

1. DSH 官方 settings 打开钩子（window 级）
2. dsh-commands 命令触发 API（无则评估 patch）
3. DSH 官方挂载点与 ui-slots slot 名清单
4. 插件中心第三方数据包安装/更新协议
5. ui-slots 公开挂载 API
