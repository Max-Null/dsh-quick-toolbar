# 方案：悬浮球「收藏会话」并入 DSH「置顶会话」

日期：2026-09-28
状态：**待审（方案，未实施）**
触发：用户观察——DSH 0.1.7 自带置顶会话，与悬浮球的收藏会话功能重叠，可以合并

## 一、问题

同一件事（把常去的会话钉到显眼处、点一下切过去）有两套实现，两套数据源：

| | 悬浮球「收藏会话」 | DSH「置顶会话」 |
|---|---|---|
| 数据位置 | 插件自管文件 `$DSH_HOME/quick-toolbar-favorites.json`（`src/index.ts:159`） | 内核 workspace media（`workspace/src/spec.ts:63` 的 `pinnedSessionIds`） |
| 作用域 | **按 workspaceId 分组**，悬浮球只列与当前会话同工作区的那份 | 注册表**全局**，但渲染时领衔各自分区（`ui-workspace/src/client/tree.ts:283`） |
| 上限 | **8 / 工作区**（`FAVORITE_LIMIT`） | **无上限** |
| 排序 | 收藏时间倒序 | 最近置顶优先（`[id, ...pinnedSessionIds]`） |
| 与归档关系 | 无约束 | **互斥**（`PinConflictsWithArchiveError`） |
| 失效会话 | 渲染时过滤（`sessionAlive`），不占名额 | `pinSession` 校验存在性；`unpinSession` **不检查**（移除不会引入未知 id） |
| 每条记录 | `title` 快照 + `cwd` + `at` | **只有 id** |
| 入口 | 悬浮球内平铺的 ☆ 按钮 + 跳转按钮 | 会话列表右键菜单 + 行内悬浮按钮 + pinned 块内拖拽排序 |

**收藏独有价值**（合并后失去的）：`title` 快照、`cwd` 排查线索、收藏时间。**但 `title` 快照的价值已经很弱**——会话列表常驻，读不到 `displayTitle` 的场景很少。

**置顶独有增益**（合并后得到的）：内核持久化（跟 workspace 走，不靠插件写文件）、无上限、与归档互斥的明确语义、pinned 块内拖拽排序、已有官方按钮。

## 二、技术前提（已核实）

悬浮球的 client 半**已经声明** `exports.inject = ['sessions', 'workspaces', 'uiWorkspace']`（`src/client.ts:1294`），并已在用：

- **会话标题**：`sessions.list.getSnapshot().byId[id].displayTitle`（`client.ts:208-210`，已有）
- **工作区归属反查**：`workspaceOf(sessionId)`（`client.ts:180-200`，已有）
- **工作区元数据**：`WorkspaceView.title` / `.sessionIds`（`api-catalog.ts:8038`）

**只差一步**：写置顶用 `uiWorkspace.pinSession` / `unpinSession`，读用 `workspaces.list.getSnapshot().pinnedSessionIds`。

**读写分两个服务的依据**：官方 UI 就是这么分工的——读走数据层的 `workspaces.list`（`ui-workspace/src/client/index.ts:146` 从 snapshot 派生 `pinnedSet`），写走 UI 层的 `uiWorkspace`（同文件 `172-177`）。两个服务都已在悬浮球的 `inject` 声明里（`client.ts:1294`），无需新增。

**失败必须处理**：官方给 pin/unpin 都挂了 notice（同文件 `170-171` 的注释：界面上什么都没动，静默失败读起来就是死按钮）。悬浮球的菜单与 ☆ 同样要处理失败分支，不能吞掉。

**菜单要手写 DOM**：悬浮球整体是纯 DOM 注入（`document.createElement` + `document.body.appendChild`，`client.ts:1073`；全文件 40 处 DOM 调用、无 React），因此**用不了内核的 `Menu` / `MenuSurface`**——那是 React 组件，且按内核约定只服务于 `packages/client/` 内的包。菜单自己画，样式取 DSH 的 CSS 变量以与周边一致。

## 三、已定决策（用户 2026-09-28）

1. **展示形式**：**二级菜单**，列**全部**置顶，**按工作区分组**。
2. **上限**：**不留**。理由：置顶数据在内核侧无上限，插件端加显示上限只会造出「明明置顶了却看不见」的假象——堵一头留一头没有意义。
3. **☆ 按钮保留**（方案评审时定），语义由「收藏当前会话」改为「置顶/取消置顶**当前会话**」。理由：悬浮球常驻，随手置顶比切到会话列表再点更顺手；与官方按钮功能重叠但**位置不同**，不构成冲突。
4. **菜单每行提供「取消置顶」**（方案评审时定），做成**小巧的次要热区**（不是每行两个等权按钮）。**失效条目必须有这个入口**——否则用户既看不见它、也删不掉它，那正是静默隐藏会留下的死角。

## 四、方案

### 4.1 数据源切换

- **读**：`workspaces.list.getSnapshot().pinnedSessionIds`（全局集合）
- **写**：`uiWorkspace.pinSession(id)` / `uiWorkspace.unpinSession(id)`（与官方一致，依据见 §二）
- **退役**：`quick-toolbar-favorites.json`、host 路由 `/quick-toolbar/api/favorites`、`src/favorites.ts`

### 4.2 入口形态

- **☆ 按钮**：语义由「收藏当前会话」变为「**置顶/取消置顶当前会话**」（写内核置顶集合）。
- **新增「置顶会话」入口**：点开二级菜单；按钮上显示置顶数量。

### 4.3 二级菜单结构

```
┌──────────────────────────┐
│ WorkStation          ③   │  ← WorkspaceView.title
│   · 会话 A            ⊖  │  ← byId[id].displayTitle + 取消置顶热区
│   · 会话 B            ⊖  │
│ 未分组                ①   │  ← workspaceId === '' 的条目
│   · 会话 C            ⊖  │
│ ──────────────────────── │
│ 没有置顶的会话时显示空态   │
└──────────────────────────┘
```

- **每行两个热区**：行体 = 跳转（`sessions.open`），行尾小图标 = 取消置顶。次要热区做小、hover 才显形，避免误触。
- **组内顺序**：跟 `pinnedSessionIds` 的顺序（最近置顶优先），与官方一致。
- **组间顺序**：按「该组在 `pinnedSessionIds` 中最先出现的条目位置」——自然且稳定，不会因重渲跳动。
- **失效条目**（id 在置顶集合里但会话已消失）：**显示为失效项并允许取消置顶**，不静默隐藏——静默隐藏会让用户既看不见也删不掉。
- **实现形态**：手写 DOM（依据见 §二），样式用 DSH CSS 变量。

### 4.4 命名冲突的处置

悬浮球自己有一个 `pinned` 状态（持久化 key `ssid-toolbar-pinned`，`client.ts:472`），含义是**悬浮球钉住展开**，与会话置顶无关。

**处置：保留持久化 key 不动**（改 key 会让用户已有的钉住状态丢失），在代码注释里写明两者的区别。菜单文案用「置顶会话」，悬浮球自身的那个继续叫「钉住」。

## 五、迁移

1. 首次运行（且旧文件存在）时，读 `quick-toolbar-favorites.json`，对每条收藏的 `sessionId` 调 `pinSession`。
2. **幂等**：已在置顶集合里的跳过（`pinSession` 对已置顶 id 本就无操作）。
3. **失效条目跳过**：会话已消失的收藏直接丢弃（`pinSession` 会拒绝）。
4. 迁移完成后把文件**改名为 `quick-toolbar-favorites.json.migrated`**（保留备份，不直接删）——文件存在即迁移，改名后自然只做一次。

## 六、边界（不做的事）

- **不改内核**：不碰 `pinnedSessionIds` 的存储格式、不碰官方 UI。
- **不保留「独立的一层收藏」**：不做「悬浮球收藏 + 内核置顶」双轨——那正是不合并的现状。
- **不动悬浮球的其它功能**：按钮聚合、LLM 注册、适配器、钉住展开都不在本次范围。

## 七、vendor 同步（本插件特有约束）

`dsh-quick-toolbar` 是 **vendor 包**：开发源在 `max-null-plugins/dsh-quick-toolbar`，打包用的副本在 `seek-soul-in-darkness/shell/profile-template/vendor/dsh-quick-toolbar`（template 的 `dependencies` 里是 `"file:./vendor/dsh-quick-toolbar"`）。

**同步是手动的。**`sync-vendor.mjs` 只处理 manifest 里 `mode: "full"` 且有真实 `source` 的包（`dsh-ssid-panels` 等）；**本包在 `check-rules.manifest.json` 里是 `vendor-only`，脚本明确声明不碰它**。所以新产物要自己复制到两处：

- `shell/profile-template/vendor/dsh-quick-toolbar`（发版基准）
- `~/.dsh/profiles/web/vendor/dsh-quick-toolbar`（web 运行时）

（`~/.dsh/profiles/ssid` 下没有 vendor 目录 —— 该 profile 走 `link:`。）

**门禁不会替你把关这一点**：`check-vendor-sync` 对 `vendor-only` 包只做**三处 vendor 互比**，不比源。两处都停在旧产物时它们彼此一致，门是绿的 —— **「门禁绿」不等于「vendor 是新的」**。复制完仍要跑 `check:rules` 确认三处一致。

## 八、验证

1. `pnpm run typecheck` + `pnpm test`（基线以改动时的实际结果为准）。
2. `node verify-quick-toolbar.cjs`（仓库自带校验脚本）。
3. **vendor 同步 + `check:rules` 六门**。
4. **实机**：置顶若干会话（含跨工作区）→ 打开菜单确认分组与顺序；点条目能切过去；☆ 置顶/取消与官方 UI 双向一致（在官方列表里置顶后，悬浮球菜单应立刻出现）。
5. 迁移验证：带旧收藏文件启动一次，确认条目进了置顶集合、文件已改名。
6. **失败分支**：pin/unpin 失败时用户能看见提示（依据见 §二），不能静默吞掉。
